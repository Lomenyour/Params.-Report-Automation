# Принятые фиксированные настройки проекта

Последнее обновление: 2026-11-03

Утверждено 03.11.2026: маппинг основной книги по ТЭЦ/ГТУ и подтверждаемые
выражения из самой книги заменяют фиксированную привязку пересчёта к СызТЭЦ.
Коэффициенты читаются из текущей книги; сохраняется история соответствий.
Пять поправок в формуле Nприв означают использование именно этих пяти.
Для Ижевской подтверждена температурная зависимость из «Своя поправка»
во всём столбце; отдельный редактор дополнительных поправок отложен.
Получасовой режим, аналитические фильтры, регрессии, перерасход и
недовыработка остаются действующими. Новые настройки и профиль входят в
экспорт; Excel и пользовательские JSON по-прежнему не коммитятся.

Уточнения 29.10.2026: белые блоки отдельных диаграмм компрессора и РХ —
14 пт. Подпись РХ: название состояния в кавычках, состояние и дата, формула
с `·`, ровно три строки. Цветные стрелки указывают на соответствующие линии.
Размер рамки определяется по метрикам Times New Roman и размеру диаграммы,
чтобы Excel не переносил строки произвольно. Другие типы подписей сохраняют
прежнюю компоновку.
Общая деградация: обозначение абсолютной дельты КПД в окошке — `%` по
соглашению пользователя (численно остаётся разность в п.п.), расход —
`нм³/МВт·ч`. Общая деградация сохраняет жирные 16 пт.
Выбор станции и ГТУ обязателен, ручной выбор имеет приоритет над именем
файла. Обозначения ГТУ строковые, включая 11Б/11В. Каталог: компании,
станции, ГТУ с моделью; тарифы новых станций неизвестны, чужие не наследуются.
Расчётная методика подключена только к СызТЭЦ ГТУ-10/11.

Этот файл перечисляет ограничения и настройки, которые сейчас заданы
константами. Они являются частью принятой методики расчёта и не подбираются
автоматически, кроме отдельно описанных статистических порогов мощности
и ВНА. Пороги разных блоков имеют разную область применения.

Актуальная версия приложения — `scr/`, соответствующая проверенному
`dist_test`. Копия `app/src/` для прежней поставки может отличаться;
текущие алгоритмы подробно описаны в `DATA_FLOW.md`.

## Разбивка на периоды

Источник: `scr/periods.py` и `app/src/periods.py`.

- `LOW_POWER = 10 МВт`: мощность `<= 10` считается остановом.
- `GAP_SIZE = 6 * 48 = 288 записей`: остановка такой длины разделяет периоды.
- `WORK_CONFIRM_SIZE = 48 записей`: для подтверждения выхода из останова нужны
  24 часа рабочих записей.
- `PERIOD_OVERRIDES = []`: пустой список включает автоматическую разбивку;
  заданный список полностью заменяет её.

## Временная шкала

Источник: `scr/data_loader.py` и `app/src/data_loader.py`.

- Одна запись данных равна `0,5 часа`.
- Часы наработки начинаются с `0` и увеличиваются на `0,5` за каждую строку.
- При обычном чтении колонка A сохраняется для контрольного сравнения с
  рассчитанными часами. При сборке нового листа «Данные» она формируется
  заново по получасовой шкале.

## Импорт выгрузки датчиков

Источник: `scr/data_assembly.py` и `app/src/data_assembly.py`.

- Из десятиминутной выгрузки выбираются замеры в `00` и `30` минут каждого часа.
- По решению пользователя поддержка всех записей/другой дискретности отложена.
  Переключатель не добавлен: наработка, окна и экономика пока получасовые.
- Автоматический словарь каналов относится только к выбранной ТЭЦ и ГТ.
  Справочник `config/stations.json` пока содержит только СызТЭЦ, ГТ-10 и ГТ-11.
  Назначения каналов пользователя сохраняются с ключами ТЭЦ и номера ГТ.
- Совмещение идёт по дате и времени. Смещение даты расчётной книги до
  `1 секунды` округляется до минуты; большее смещение останавливает импорт.
- При совпадении даты новые показания заменяют старые; повтор дат в любой
  входной таблице считается ошибкой.
- Давление в мм рт. ст. переводится в Па множителем `133,322368`, давление
  в мм вод. ст. — множителем `9,80665`.
- Коэффициенты перевода можно исправить в окне сопоставления каналов.
- Значения `X` остаются нечисловыми; в расчёте соответствующей точки
  результат недоступен, а в логе показывается количество таких значений.
- Значения давления уходящих газов записываются в колонку `AC` под заголовок.
- Для повторной сборки книги результатов используемые числовые
  поправки и постоянные сохраняются по станции и номеру ГТ в локальном файле
  `%LOCALAPPDATA%\GTU_Report\calculation_profiles.json`. При первом запуске
  нужна исходная расчётная книга с листами «Поправки» и «Результаты».

## Режимы приложения и экспорт результатов

Источник: `scr/app.py`, `scr/result_export.py`.

- По умолчанию выбран режим расчёта готовой книги. Выгрузка датчиков
  используется только в режиме обновления данных.
- В обоих режимах успешный расчёт сохраняет результат только в памяти
  приложения и показывает вкладки. Excel, Word и промежуточный JSON
  автоматически не записываются.
- После расчёта доступны отдельные кнопки «Сформировать Excel» и
  «Сформировать Word». Путь выбирается при нажатии соответствующей кнопки;
  оба документа формируются из одного снимка результата без нового расчёта.
- Общая папка сохранения по умолчанию для Excel и Word — `data/output`
  в корне проекта. Она создаётся при открытии окна сохранения. Тестовая
  сборка в `dist_test/` использует эту же папку проекта; при переносе EXE
  отдельно от проекта используется `data/output` рядом с EXE.
- Excel содержит основные листы «Данные», «Таблицы», «Графики» и видимый
  листы «Данные компрессора» и «Данные РХ» с данными соответствующих диаграмм.
- Кнопка запуска после первого прогона называется «Перерасчёт»: повторно
  читает текущие выбранные файлы и снова предлагает выбрать периоды.
  Перед повторным запуском прежний результат для экспорта сбрасывается.
- Экспорт выполняется в отдельном потоке. Во время расчёта и экспорта
  входы и кнопки запуска/формирования документов заблокированы.
- В режиме готовой книги лист «Данные» содержит исходные значения первого
  листа основной книги с прежним порядком строк. Формулы сохраняются как
  рассчитанные значения из книги.
- При импорте лист «Данные» содержит объединённые измерения и заново
  рассчитанные производные колонки.
- На листе «Таблицы» сохраняются периоды, параметры на границах, все строки
  TOP-10 ВНА каждого периода, дельты, наработка и экономика.
- На листе «Графики» размещаются диаграмма перепадов с таблицами граничных
  точек, общая диаграмма деградации ГТУ, диаграммы компрессора и РХ по периодам.
- При смене режима, файлов, листа выгрузки, соответствий, событий графика
  или тарифов прежний результат для обоих документов сбрасывается.

## Диаграмма перепадов в Excel

Источник: `scr/pressure_chart.py`.

- Нативная редактируемая XY-диаграмма: все точки выбранных данных по времени,
  без усреднения и прореживания. Слева перепады в Па, справа фактическая
  мощность `N` в МВт. Оформление — по референсу СызТЭЦ ГТ-10.
- Шкала перепадов — от `0` минимум до `500 Па`, основные деления через
  `50 Па`, дополнительные через `10 Па`. При больших значениях верхняя
  граница расширяется. Шкала мощности — `50–100 МВт`; если максимальная
  мощность ниже `50 МВт`, нижняя граница равна нулю, а при превышении
  `100 МВт` верхняя граница расширяется. Это только отображение.
- Цвета: `N` — красный `C00000`, ВЛО — синий `0070C0`, ФГО и совмещённый
  ФГО+ФТО — зелёный `00B050`, отдельный ФТО — голубой `00B0F0`.
- Если есть заполненный совмещённый канал ФГО+ФТО, используется он;
  иначе выводятся доступные отдельные ФГО и ФТО.
- Начало и конец точек граничной таблицы отмечаются чёрными
  вертикальными линиями. Сверху — двусторонняя стрелка и белый блок
  с номером периода и теми же датами точек. Расчётные периоды не меняются.
- Внутри графика у границ — белые блоки: дата номинальной точки,
  доступные перепады, ВНА и фактическая N. Точки берутся из той же
  таблицы «Параметры на границах», что и полные таблицы под диаграммой.
  При близких границах блоки сдвигаются по горизонтали, чтобы не перекрываться.
- Шрифт осей, делений и легенды — Times New Roman 16 пт;
  белых блоков — 10 пт. Размер блоков подстраивается под текст.
  В обозначениях ΔPВЛО, ΔPФГО+ФТО (либо отдельных ΔPФГО/ΔPФТО), αВНА и NГТУ
  индекс уменьшен до 75 % основного кегля и опущен на 25 % строки.
  Легенда снизу. Временная шкала
  имеет отступы по `10 %` диапазона данных с каждого края, основные
  и дополнительные линии сетки; даты отображаются как `дд.мм.гггг`.
- События вводятся вручную отдельной кнопкой приложения: одна строка
  `дд.мм.гггг [чч:мм]; подпись`. Они сохраняются по станции и ГТ в
  `%LOCALAPPDATA%\GTU_Report\chart_events.json`, для книг без номера ГТ —
  по пути книги. Событие в видимом диапазоне отмечается чёрной линией
  с вертикальной подписью. Даты событий не участвуют в расчёте периодов.
- Под диаграммой на каждый период размещаются две таблицы с теми же
  номинальными точками и параметрами, что вкладка «Параметры на границах»:
  первая/последняя рабочая точка внутри периода с ВНА ≥ T данного периода.
  T — максимальный порог, оставляющий не менее 80 % допустимых рабочих
  показаний ВНА; при получасовой дискретности это доля времени. Порог
  округляется вниз до 0,1 %. Число и даты расчётных периодов не меняются.
- Размер диаграммы — `42×18 см`, таблицы начинаются со строки `40`, по
  два периода в ряд. Печать — A3, альбомная ориентация, две страницы по ширине
  при наличии графика деградации.
- Служебные диапазоны скрыты в колонках `AX:BH` листа «Графики» и связаны
  формулами с листом «Данные». Нечисловые и отрицательные показания не
  превращаются в нулевые точки; в служебных ячейках используется `#N/A`.
- Справа от графика перепадов строится нативная диаграмма деградации `42×18 см` по
  доминирующему одноградусному интервалу ВНА каждого периода. Её служебные
  значения лежат в скрытых колонках `BJ:BN`; таблица периодов — под ней.
  Левая ось строго `0–350` с шагом основных линий `50` и дополнительных `10`,
  правая ось ВНА — `65–100%`. Ось дат расширена на два календарных месяца
  до первой и после последней показанной точки. Оси, деления и легенда —
  Times New Roman 16 пт; индексы прив/ГТУ в обозначениях параметров подстрочные.
  Для каждого периода добавлены блоки Δbприв, интервала регрессии ВНА,
  ΔNприв и Δη ГТУ: жирный текст 16 пт, по готовой таблице, без нового расчёта дельт.
- Соседние короткие периоды: подписи дельт раздвигаются по высоте
  отдельно для каждого параметра с шагом `20` единиц левой оси, если центры
  ближе `20 %` ширины шкалы дат. Блоки КПД не вытесняются в область мощности.
  Для верхних подписей перепадов используются уровни `97 %` и `90 %`
  высоты при расстоянии центров менее `11,5 %` шкалы дат. Даты не сдвигаются.

## Диаграммы компрессора по периодам

Размер отдельной диаграммы — 18 столбцов × 32 строки, привязка к двум
границам ячеек. Общая диаграмма ГТУ остаётся 42×18 см.
Блок размещения — 40 строк; в двухколоночном режиме начала диаграмм A/U.

Оформление периодных диаграмм компрессора (`scr/compressor_degradation_chart.py`):
белые область диаграммы и поле построения, чёрные подписи Times New Roman:
10 пт в белых блоках, 16 пт на осях и в легенде. Индексы нк/oi/к
в обозначениях tнк, Pнк, ηoi и πк — подстрочные.
Центральный блок содержит только три строки ВНА/tнк/Pнк, десятичный
разделитель — запятая; фильтр КПД сохраняется в данных и их описании.
Основные линии сетки чёрные, дополнительные серые, по обеим осям;
легенда содержит только «КПД» и «Степень сжатия».
Пределы обеих вертикальных осей определяются по своим точкам, без изменения
значений. Кривые разнесены по высоте: КПД в верхней части, πк — в нижней.
Минимальный размах — 6 п.п. для КПД и 5 о.е. для πк. Основной шаг
не меньше 1, выбирается из `1/2/5/10 × 10^k`; дополнительный — в пять раз меньше.
КПД центрируется около 70 % высоты, πк около 25 %; все точки остаются видимыми.
Сетка есть только у основных осей. Числа в блоках — с одним знаком,
без округления исходных точек или границ фильтрации.
Ось дат имеет поля по 10 % длительности выборки, минимум сутки с каждой стороны.
Шаг подписей подбирается к 8–10 датам, минимум сутки, чтобы даты не дублировались.
Уравнения и R² трендов
скрыты, сами линии трендов остаются редактируемыми.

Данные компрессора хранятся блоками на одном видимом листе «Данные компрессора», а не в скрытых
колонках листа «Графики». Помимо ВНА, температуры и давления, для графика
применяется `min(η₁, η₂) ≤ ηoi ≤ max(η₁, η₂)` по значениям TOP-1.
Температура, давление и КПД сравниваются на точности TOP-10 — три знака;
исходные значения ячеек и рядов при этом не округляются. Внутри диаграммы —
три белых блока: условия отбора (90% высоты) и данные начальной/конечной
точек (48% высоты), привязанные к датам TOP-1. Подписи и стрелки используют
собственные координаты диаграммы и не создают скрытых диапазонов на листе.

## Регрессии RH

Источник: `scr/RH_raschet.py` и `app/src/RH_raschet.py`.

- Размер окна регрессии: `48 записей`.
- Зона поиска в начале и конце периода: `10 суток = 480 записей`.
- Допуски при подборе пар окон: `5%` для коэффициента мощности и `5%` для
  коэффициента расхода.
- Расчёт сохраняет до `3` вариантов на период. Для графика выбирается
  первый с `k_end >= k_start`; если такого нет — первый вариант периода.
  Выбор общий для GUI и Excel, не меняет поиск кандидатов и экономику.
- РХ в Excel: одна диаграмма на период с точками и двумя регрессиями.
  Даты состояний — первые даты выбранных окон START и END. Синяя серия —
  условно-чистая, красная — условно-загрязнённая; оси/легенда 16 пт,
  подписи состояний и уравнений 10 пт. Масштаб по данным.
- РХ в GUI: сетка до трёх периодов в ряд, ячейка `9×6 дюймов`.
  В Excel размер диаграммы — 14 столбцов × 33 строки; данные всех периодов
  расположены блоками на одном листе «Данные РХ».
  Блок размещения — 38 строк, начала диаграмм A/Q. Поле построения имеет
  левый отступ 16 % под подпись оси и числа; деления расхода без десятичных.
- Регрессии по `Nприв`, `bприв` и `ηГТУ` строятся в наиболее частом
  однопроцентном интервале ВНА периода.
- Исходная дельта всех трёх метрик знаковая:
  `Δ = k * (часы конца − часы начала)`.
- Колонки «до отсечки» сохраняют исходные изменения. В основных колонках
  показывается только деградация: `ΔNприв = min(ΔNисх; 0)` со знаком снижения,
  `Δbприв = max(Δbисх; 0)`. Процентные колонки используют те же отсечённые
  дельты. Отсутствие расчётных данных остаётся пропуском, а не нулём.
  КПД в этой правке остаётся знаковым, без новой отсечки.
- В средневзвешенном итоге берётся только деградация: для мощности
  `max(−ΔNприв; 0)`, для удельного расхода `max(Δbприв; 0)`; веса —
  длительности периодов. Улучшение не исключает длительность периода
  из знаменателя. Методика и результаты сводки не меняются.

## Номинальный режим

Источник: `scr/RH_raschet.py` и `app/src/RH_raschet.py`.

- Для граничной таблицы используется индивидуальный порог ВНА по покрытию
  не менее 80 % рабочих записей в каждом уже принятом периоде. Это
  изменение не применяется к автоматической разбивке и расчётным часам.
- Для отдельного показателя часов по ВНА сохраняется `ВНА ≥ 80%`; дополнительно
  исключаются строки с мощностью `<= 10 МВт`, чтобы считать именно наработку.
- Порог мощности не задан одним фиксированным числом. Из распределения
  `Nприв` исключаются значения `<= 10 МВт`, затем мощностные интервалы по
  `10 МВт` набираются от верхних к нижним до `80%` рабочих записей. Нижняя
  граница последнего вошедшего интервала становится условием `Nприв ≥ порог`.
- Распределения для общей наработки и экономики ограничены принятыми
  периодами; отдельный порог для каждого периода не вводится.

## ВНА

Источник: `scr/VNA_full.py` и `app/src/VNA_full.py`.

- Максимальная разница температур в допустимой паре: `0,5 °C`.
- Максимальная разница давления: `5,0 мбар` (`500 Па`).
- Сетка интервалов ВНА: шаг `0,1°`.
- Ширина гибкого окна: от `0,1°` до `1,0°`.
- Допуск КПД при поиске каждой пары TOP-10: строго `Δη < 0,8 п.п.`,
  одновременно с допусками температуры и давления.
- В итог попадает не более `10` интервалов на период.
- Рабочий диапазон ВНА: от `0` до `100%`.
- Обзорная гистограмма строится с шагом `1°`, метки оси идут через `5°`.
- Сортировка TOP-10: `delta_days` по убыванию, затем количество точек по
  убыванию, затем `delta_eta` по возрастанию.

## Чтение книги и физическая модель

Источник: `scr/data_loader.py` и `scr/VNA_full.py`.

- Читается только первый лист книги, который должен называться `Данные`.
- Строка заголовка ищется только в первых `25` строках.
- Для распознавания заголовка требуется минимум `2` известных названия.
- Тип `Pнк` определяется эвристикой `Pнк / Pатм > 0,5`.
- В CoolProp для энтальпии газа пока используется только `Methane`.
  Полный состав газа из таблицы компонентов пока не подключён.
- Физические константы перевода единиц и температуры (`273,15`, `100`,
  `10`, `10^6`, `3600`, `1000`, `101325`) заданы по используемой методике.
- Точки с некорректным сжатием (`P1 <= 0` или `P2 <= P1`) исключаются из
  расчёта КПД компрессора.

Уточнение для текущего `scr/` (2026-10-23): TOP-10 и графики компрессора
используют готовый `ηoi_Cprop` первого листа `Данные`, без повторного физического
расчёта. При сборке из датчиков эту колонку один раз заполняет `data_assembly.py`.
При отсутствии колонки расчёт ВНА сообщает ошибку; ячейки с пропусками КПД
не участвуют в парах и графиках компрессора. Физическое ограничение диапазона
готового КПД дополнительно не вводилось. КПД ГТУ остаётся отдельным расчётом.
Подробный актуальный ход алгоритмов: `DATA_FLOW.md`.

## Экономика

Источник: scr/economics.py и app/src/economics.py.

- Старые фиксированные фильтры Nприв > 80, ВНА >= 79, ВНА >= 86 и
  Nприв >= 88 в экономическом расчёте не используются.
- Общий порог ВНА для экономического расчёта строится по принятым периодам,
  только по рабочим строкам (Nприв > 10), с шагом 1°. Верхние интервалы
  набираются до 80% рабочих записей; затем используется ВНА ≥ порог.
- Порог мощности берётся из общего распределения Nприв по правилу
  номинального режима. Потери суммируются только внутри принятых периодов
  на строках, одновременно удовлетворяющих Nприв ≥ порог мощности и
  ВНА ≥ порог ВНА, с проверками качества расхода и температуры.
- Фильтр качества bприв: строго 150 < bприв < 600.
- Фильтр температуры воздуха: строго −40 < T < 50 °C.
- Регрессия для экономики строится в самом частом однопроцентном интервале
  ВНА каждого периода. Потери усредняются по двум соседним получасовым
  записям и затем суммируются за период.
- Тариф газа, тариф электроэнергии и себестоимость электроэнергии вводятся
  из профиля выбранной ТЭЦ, с возможностью ручного изменения на текущий
  расчёт. Для СызТЭЦ: газ `7,773 руб/нм³`, ЭЭ `2253,66 руб/МВт·ч`,
  себестоимость `1200 руб/МВт·ч`. Денежная недовыработка считается по разнице
  `тариф ЭЭ − себестоимость ЭЭ`.
- В экономике учитывается только положительная потеря: рост bприв даёт
  перерасход, снижение Nприв даёт недовыработку. Знаковые дельты
  основного отчёта остаются без отсечки.
- Приведение итоговых потерь к году эксплуатации использует `8760` ч,
  разделённые на сумму `(Часы конца − Часы начала)` всех принятых периодов.

  проверка ключевых колонок отклоняет чужую раскладку. Методика Ижевской
  не подключается импортом и не наследует коэффициенты СызТЭЦ.

### Выбор параметров и единиц (02.11.2026)

- Меню `choice_field.js`: высота до 280 px, отступ от экрана 12 px, зазор
  до поля 4 px. Если снизу менее 220 px и сверху больше места, открывается
  вверх. Минимальная желаемая ширина параметров 330 px, единиц — 190 px,
  ограничена экраном. Повторное открытие показывает все варианты.
- `unit_conversions.py` — единый Python/HTML справочник множителей/алиасов.
  30 обозначений. м³/ч → м³/с = 1/3600, об/мин → Гц = 1/60,
  тыс. об/мин → Гц = 1000/60, т/ч → кг/с = 1000/3600, % → о.е. = 0.01.
  Давления сохраняют прежние коэффициенты. Нормальный/рабочий объём и
  массовый/объёмный расход — разные группы; температурные сдвиги запрещены
  для модели одного множителя. Число в форме — до 10 значащих цифр,
  подтверждение использует полную точность справочника.
- Из описания извлекается только целая известная единица, начиная с самого
  длинного обозначения. Нельзя отбрасывать нормальный объём/тысячи оборотов;
  неизвестное составное обозначение не сокращается до знакомого суффикса.
- Принудительного «До уточнения» в форме больше нет. Старые записи с этим
  статусом показываются без назначения для явного выбора пользователем.
- Ручной выбор единицы источника из собственного JSON имеет приоритет;
  исходное обозначение файла показывается отдельно. При известной паре
  коэффициент вычисляется автоматически, несовместимая пара не подтверждается.

### C/H и «Не учитывать» (02.11.2026)

- `combustible_mass_v1`: C/H = 12.011 Σ(x·nC) / [1.008 Σ(x·nH)] по горючим
  компонентам с H₂, без CO₂/N₂/O₂/He. Атомные массы CIAAW 2024, формулы NIST.
  Версия/константы и совместимость закреплены в `GAS_CH_CALCULATION.md`.
- C/H readonly, первая строка параметров. Python заново считает при сохранении.
  Старые явные C/H читаются для воспроизводимости; сохранение паспорта через
  новую форму переводит его на расчёт по составу. Порог суммы долей — 0.001.
- Без водорода C/H не определено; чистый H₂ имеет C/H=0. Неизвестные ненулевые
  компоненты не пропускаются. Состав не нормализуется автоматически.
- «Не учитывать» — опциональный `ignored`, без автоприсвоения тегу. Показания
  канала не импортируются, основные данные не стираются. Статус обратим и
  сохраняется по ТЭЦ/ГТ/набору; поля единиц/коэффициента отключаются.
- Историческая блокировка по `syz_tec_v1` заменена 03.11.2026 обязательным
  подтверждением параметров основной книги. Для импорта нужны поддерживаемые
  выражения и текущие коэффициенты; для готового режима — необходимые значения.
