# Правило работы с изменениями

Перед любым изменением проекта сначала нужно сообщить пользователю:

1. точную формулировку задачи;
2. предлагаемое техническое решение;
3. какие файлы и части проекта будут затронуты;
4. дождаться подтверждения пользователя.

Изменения в код вносить только после такого подтверждения. Если пользователь
просит отменить изменение, сначала вернуть прежнее поведение и проверить его.

Исходный код хранится и коммитится в `scr/`. Word-шаблоны в
`word_auto/templates/` и в Desktop Test также отслеживаются с 29.10.2026.
Перед сборкой выполнить синхронизацию шаблонов, никогда не затирать
несовпадающие версии молча. Принцип и полный список исключений —
`GIT_TRACKING.md`. EXE и `_internal` не добавлять в Git: пользователь
уточнил, что требуется сохранять исходники, а не бинарные файлы сборки.
