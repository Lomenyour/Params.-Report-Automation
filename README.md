## Запуск из исходников в Windows

Проверенное окружение — Python 3.14.7 и PySide6 6.12.0. Из корня проекта:

```powershell
py -m pip install -r requirements.txt
py scr/desktop_bootstrap.py
```

В приложении выберите готовую книгу либо режим обновления данными датчиков.
Для расчётной книги используется только первый лист с именем `Данные`.
После автоматического определения периодов можно просмотреть график и
подтвердить или исправить даты. Результаты появляются во вкладках.
Выбор ТЭЦ обязателен в обоих режимах; пока в списке только СызТЭЦ.
Станция определяется по имени книги, выбор можно исправить вручную.
Три тарифа подставляются из профиля ТЭЦ и остаются редактируемыми:
газ 7,773 руб/нм³, ЭЭ 2253,66 руб/МВт·ч, себестоимость 1200 руб/МВт·ч.
Словарь датчиков также относится к выбранной ТЭЦ и номеру ГТ.
Структура справочников и их перенос в БД описаны в [config/README.md](config/README.md).
Импорт по-прежнему выбирает только получасовые записи; другую дискретность
и полный самостоятельный пересчёт производных колонок пока отложили.

Газовый паспорт и перенос поправок (28.10.2026): backend поддерживает
редактирование плотности, Qнр, C/H и состава отдельно для ТЭЦ/ГТ. Пользовательский
справочник — `%LOCALAPPDATA%/GTU_Report/gas_passports.json`; новый Excel хранит
использованный паспорт на перенесённом листе «Поправки». Кнопка «Паспорт газа»
находится под выбором ТЭЦ и открывает готовый редактор. Она доступна после
выбора книги и ТЭЦ, когда расчёт и экспорт не выполняются. Подключение:
действие `gasPassport`, состояние `gas_passport_button`.
Подробности и ограничения совместимости — раздел 16 [DATA_FLOW.md](DATA_FLOW.md).
Паспортные значения могут изменить результат; перенос профиля сам по себе
не меняет результаты повторного расчёта. Автоматическая адаптация колонок и
JSON коэффициентов поправок в эту итерацию не входили; обновление 29.10 описано ниже.

Историческая реализация поправок (29.10.2026): кнопка «Поправки ГТ» открывала редактор
63 коэффициентов в десяти группах. Профили сохраняются отдельно по ТЭЦ/ГТ в
`%LOCALAPPDATA%/GTU_Report/correction_profiles.json`. В обычном расчёте
используется JSON либо именованный набор из экспортированной книги;
адреса ячеек старого шаблона не читаются. Для СызТЭЦ ГТ-10 и ГТ-11 на текущем
компьютере исходные значения перенесены однократно. Реальные JSON и таблица
значений остаются локально, в Git и EXE не включаются.
Порядок полей, формулы и подсказки — [CORRECTION_PROFILES.md](CORRECTION_PROFILES.md).
В редактор можно вставлять диапазон чисел из Excel. Изменение профиля требует
перерасчёта; тогда готовая книга обновляла реализованные коэффициентные поправки.

В актуальной Rotor Test от 05.11.2026 «Поправки ГТ» открывает единое окно
маппинга основной книги с просмотром формул и коэффициентов. Дублирующая
кнопка «Колонки основной книги» удалена из боковой панели. Назначения
сохраняются по ТЭЦ/ГТУ. Выражение выбирается по
большинству строк. Старый JSON `correction_profiles.json` в этом сценарии
не подставляется. Подробности — [WORKBOOK_MAPPING.md](WORKBOOK_MAPPING.md).
В просмотре формул используется запись с именами параметров, исходная Excel-
формула доступна в расшифровке. Безымянные столбцы скрыты из маппинга и
сохраняются в расчётной модели; сообщение о постоянной E=1 убрано.

Слева находятся исходная книга, ТЭЦ, режим и тарифы. Кнопка «Расчет»
закреплена внизу; после первого прогона она называется «Перерасчет».
Базовая ширина панели подготовки — 324 px. Потяните границу справа от
панели, чтобы изменить её ширину; двойной щелчок возвращает исходную.
Выбранная ширина сохраняется локально. Поле станции подписано «ТЭЦ»,
режим импорта — «Добавить выгрузку с датчиков».
Справа доступны разделы: Перепады, ВНА, Границы, ТОП-10, Деградация,
RH, Экономика. Кнопки разделов переносятся при недостатке ширины;
журнал расчёта снизу можно свернуть. Настоящее оформление находится в
`scr/desktop_ui/`; Python-адаптер `scr/desktop_controller.py` подключает
к нему прежние обработчики из `scr/app.py`. Сервер и Интернет не нужны.
Графики отображаются из памяти; масштабирование не меняет исходные Figure
и документы. Прежнее оформление Tkinter находится в `scr/ui_theme.py`.

Выбран белый фронтальный значок турбины без квадратной плашки. Он отображается
в шапке интерфейса, системном значке окна и тестовом EXE. Исходный PNG

Уточнения UI 30.10.2026: между «Паспорт газа» и «Поправки ГТ» добавлено

результатов заменяется турбиной: крыльчатка вращается с оборотом за 6 секунд,
корпус неподвижен. Готовые графики и таблицы показываются как прежде;

Кнопки «Excel» и «Word» над результатами предлагают выбрать путь.
По умолчанию используется локальная папка `data/output`. Документы
автоматически после расчёта не сохраняются.

В Excel даты верхних подписей и блоков перепадов совпадают с граничной
таблицей: её порог ВНА определяется отдельно по 80 % допустимых рабочих
наблюдений каждого периода. Автоматическая разбивка и ручные периоды
сохраняют прежнюю логику. Общая диаграмма деградации показывает дельты
из таблицы; на период выводится одна РХ по условию `kкон ≥ kнач`, либо
первый вариант, если подходящего нет. Данные диаграмм находятся на видимых
листах «Данные компрессора» и «Данные РХ». Оси/деления/легенды — 16 пт;
блоки общей деградации ГТУ — жирные 16 пт, остальные блоки — 10 пт.

Прежний консольный запуск также доступен:

размещаются в `data/`. Консольный сценарий запускает VNA и RH на общих данных.

## Word и сборка EXE

Для Word положите свой шаблон в
`word_auto/templates/template_mapped.docx`. С 29.10.2026 он хранится в Git,
как и редактируемая копия единственной Rotor Test. Перед сборкой версии синхронизируются
с резервированием; конфликтующие правки не перезаписываются молча.
Подробности и исключённые папки — [GIT_TRACKING.md](GIT_TRACKING.md).
Список полей и правила шаблона: [TEMPLATE_MAPPING.md](word_auto/TEMPLATE_MAPPING.md).
Перед сборкой EXE папка с шаблоном также должна быть подготовлена.

```powershell
py -m pip install pyinstaller==6.22.3
powershell -NoProfile -File .\build_gui.ps1
```

Перед пересборкой закройте тестовый EXE, сохранив нужные результаты.
Каждая сборка заменяет ту же папку `dist_test/GTU_Report_Rotor_Test/`;
для запуска нужна вся соседняя папка
`_internal`, включая Qt WebEngine, локальные файлы интерфейса и ресурсы.
Имя зафиксировано: `GTU_Report_Rotor_Test`. Другое значение `-Name`
отклоняется до начала сборки. Если приложение открыто, не создавайте
дополнительную версию для обхода проверки: сначала закройте тестовый EXE.
При сборке каталоги сторонней ICU (например Poppler) временно исключаются
из PATH процесса PyInstaller: Qt использует системную ICU Windows.
Это предотвращает подхват несовместимой DLL и не меняет PATH пользователя.
Скрипт обновляет только тестовую сборку. Текущие исходники находятся в `scr/`;
`app/src/` — отдельная копия для прежней поставки коллеге, её обновление
выполняется отдельно. Подробнее: [BUILD_VARIANTS.md](BUILD_VARIANTS.md).
