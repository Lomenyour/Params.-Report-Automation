# Добавление ТЭЦ и проверка новых книг — 11.11.2026

## Реализация

Рядом со списком ТЭЦ одна кнопка «Добавить ТЭЦ». В той же форме задаются
номер и модель первой ГТУ; отдельной кнопки добавления ГТ нет. Компания,
родительный падеж для Word и варианты имени файла необязательны. Номер
ТЭЦ в имени «КазТЭЦ-1» не используется как предположение о номере ГТУ.

Список ТЭЦ сортируется А–Я с естественным порядком чисел и равным порядком
е/ё. После создания выбираются новая станция и ГТУ, обновляются модель,
тарифные поля и доступность паспорта. Смена станции сбрасывает прежний
аналитический снимок как обычная смена входных данных; отмена формы его
сохраняет. Создание справочной записи не запускает аналитику.

Записи хранятся в `%LOCALAPPDATA%/GTU_Report/user_stations.json` отдельно
от базового каталога. ID станции создаётся один раз и сохраняется; модель,
варианты имени и Word-название восстанавливаются после перезапуска.
Перед атомарной записью повторно читаются актуальные дополнения и проверяется
полный объединённый каталог. Базовый JSON не изменяется. Сбой записи
сохраняет прежний пользовательский файл и прежнее состояние репозитория.

Проверяются обязательные поля, номер ГТ, точные нормализованные названия
и уже известные варианты имени. Нечёткий поиск похожих названий отсутствует.
Чужие тарифы, каналы и числовые паспорта новой станции не присваиваются.
Редактор паспорта получает новый ID станции и номер ГТ; после заполнения
паспорт сохраняется обычным механизмом в `gas_passport_history.json`.

## XLSB: подтверждённая граница поддержки

`data/КазТЭЦ-1.xlsb` прочитан без конвертации: первый лист «Данные»,
29 384 строки после заголовка, 73 колонки. Это проверка чтения структуры
и готовых значений. Полный аналитический расчёт конкретной книги не запускался.

В режиме готовой книги `_calculation_worker` использует
`book_setup.canonical(layout.values)`, а `validate_recalculation` и исполнение
выражений вызываются только в ветке импорта выгрузки. Поэтому `.xlsb` подходит
для анализа готовых сохранённых значений при подтверждённом маппинге.
Для извлечения выражений самого XLSB встроенный разборщик не реализован:
для импорта с пересчётом нужны `.xlsx/.xlsm` либо переносимый профиль формул.
Сохранение исходной книги средствами установленного Excel — отдельная ветка.

## ФСО в Кировской ТЭЦ-3

На первом листе `Кировская ТЭЦ-3 2026 3 квартал.xlsx` найдены:

| Колонка | Заголовок | Формула основной структуры |
| --- | --- | --- |
| K | ФСО, Па | Измерения, 9813 числовых значений |
| L | ФГО, Па | Измерения |
| M | ФТО,Па | Измерения |
| N | Δpнк, Па | `SUM(K2:M2)` |
| C | Pатм, Па | `O2*100+N2` |
| P | kΔРвхN | `Поправки!$B$91*N2+Поправки!$D$91` |
| Q | kΔРвхη | `Поправки!$H$91*N2+Поправки!$J$91` |
| AS | Nприв, МВт | `AQ2/(D2*H2*P2*W2*AF2)` |
| AW | Bприв, нм3/ч | `AS2/((AQ2/AU2)/(I2*Q2*AG2*X2))` |

Колонки книги читаются динамически. Список назначений справа в маппинге
берётся из фиксированного `workbook_profile.ROLES`, где ФСО отсутствует.
По умолчанию K остаётся вспомогательной измеряемой колонкой. Она сохраняется
в исходных данных и доступна как вспомогательный вход формул. В готовых
приведённых показателях влияние ФСО, предусмотренное исходными выражениями,
сохраняется при использовании этих готовых значений.

Отдельного ряда ФСО нет: графики GUI/Excel, таблица границ и Word-дельты
перечисляют ВЛО/ФГО/ФТО/ФГО+ФТО. Это отдельное расширение модели параметров;
данная задача не меняет роли, формулы и графики ФСО. Проверены структура,
числовая представленность K и ссылки формул, без очистки или изменения данных.

## Проверки

**276 unittest — OK.** Восемь новых проверяют сортировку, создание и повторное
чтение, точные совпадения/варианты имени, ошибочные поля, сбой записи,
повреждённый JSON, сохранение дополнений при устаревшем экземпляре репозитория
и сохранение/чтение отдельного паспорта новой пары. SHA-256 базового каталога
остаётся прежним.

```powershell
py -X utf8 -m unittest discover -s tests -p test_*.py -v
py -X utf8 tests/qa_station_creation_ui.py
py -X utf8 tests/qa_source_book_and_log_ui.py
```

Qt/HTML проверяет настоящую кнопку и модальную форму: отмена, валидация,
сохранение, выбор новой ТЭЦ/ГТ, сортировка, пустые поля своего паспорта,
перезапуск репозитория, блокировка во время операций и отсутствие аналитики.
Форма и интерфейс при 900×600/1200×800 проверены визуально.
Прежний QA исходной книги/полного журнала прошёл. В окружении проверки
Win32 `OpenClipboard` возвращает отказ в доступе (ошибка 5), поэтому
нативное обратное чтение буфера пропущено; полный передаваемый текст
проверен через `setText`. Код копирования приложения не менялся.
