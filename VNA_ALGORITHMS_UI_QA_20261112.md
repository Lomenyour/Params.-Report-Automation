# ТОП-10 ВНА: два алгоритма и интерфейс — 12.11.2026

## Область работы

Пользователь поручил проверить прежний алгоритм, добавить второй по числу
реальных точек графика, привести элементы интерфейса к приложенному образцу
ChatGPT/Codex и уменьшить начальный размер графиков ТОП-10. Подтверждено:
для каждого окна ВНА сохраняется только одна лучшая пара. Новые расчётные
книги и выбор нескольких РХ оставлены на следующие этапы. Шаблон Word
этой работой не редактируется. Фиксированные решения записаны в
`HARD_CODED_SETTINGS.md` до реализации.

## Проверка алгоритма 1

Прямой полный перебор выбирает строки окна по числовым условиям
`lower ≤ ВНА < upper`, затем перебирает все пары по допускам. Для 55
контрольных наборов проверены все пересекающиеся окна, максимальная разница
дат, численность окна и его наиболее узкий представитель. Включены точные
десятичные границы, повторяющиеся даты и пропуски КПД. При одинаковых
временных метках проверяется максимальный размах; новый приоритет между
равными по дате измерениями прежнему методу не навязывается.

Найдены и исправлены численные дефекты, не меняющие принцип ранжирования:

- `floor(86.1 / 0.1)` мог включить ВНА 86,1 в окно 86,0–86,1, из которого
  действующий график затем исключал эти точки. Теперь ячейка определяется
  бинарным поиском десятичных границ, с включением левой границы.
- `16.1 − 15.6` мог превышать 0,5 только из-за представления float.
  Разности t/p сравниваются после округления до 12 знаков, аналогично уже
  существующей строгой проверке Δη. Пороги 0,5 / 5 / 0,8 не увеличены.
- ВНА ровно 100 не входит ни в одно полуоткрытое окно до 100 и больше
  не помещается искусственно в последнюю ячейку. Сам сигнал, исходные строки
  и обзорная гистограмма сохраняются; знаменатель доли окна прежний.

На 20 обычных синтетических наборах все 1387 кандидатов после точности
отчёта совпали с кодом исходного коммита `f6bb96e`, включая все поля пары.
Воспроизведение: `py -B tests/qa_vna_legacy_comparison.py`.
Остаются прежние сортировка Δдней ↓ / count ↓ / Δη ↑, удаление повторов
Δдней с тремя знаками и лимит 10.

## Алгоритм 2

`scr/vna_density.py` ищет одну оптимальную пару каждого окна. Цель — число
точек после действующих фильтров GUI/Excel, а не число строк `count`.
Сетка/ширины окон и допуски прежние; размах пары ≥ 2/3 полных принятых
границ периода. Дополнительного ограничения датами самой пары нет:
так работает существующий `prepare_compressor_plots`.

При равенстве: больший размах, меньшая Δη, ранние позиции строк.
Одинаковые наборы графических точек объединяются; при полном равенстве
выбираются узкое окно и меньшая левая граница. Разные графики могут
иметь одинаковые Δдней. В таблице добавлен `plot_points`, `count` сохраняет
прежний смысл. Нет ослабления порогов, коротких пар или подмены методом 1
при отсутствии результата.

Сравнены три способа поиска: независимый полный перебор для проверки;
матрица всех пар с большим расходом памяти; точный поиск с битовыми
масками строк, группировкой одинаковых параметров и верхними границами
числа точек. Выбран третий. Группировка сохраняет крайние даты:
между одинаковыми группами отбор графика один и тот же, поэтому более
длинная пара доминирует. Отсечения выполняются только по доказуемой
верхней границе; эвристического ограничения числа кандидатов нет.
Кеш диапазонов ограничен 4096 запросами. Перебор в сложных случаях
может быть медленнее; работа выполняется в фоне.

Официальные определения использованных операций:
[NumPy searchsorted](https://numpy.org/doc/stable/reference/generated/numpy.searchsorted.html),
[Python int.bit_count](https://docs.python.org/3/library/stdtypes.html#int.bit_count).

Независимый oracle в `tests/test_vna_density.py` перебирает окна и все пары,
затем сам выполняет отбор строк. Совпали 45 случайных наборов и отдельные
случаи: равенства/группы/дубликаты, полный период вместо отфильтрованного,
строгая граница 2/3 с точностью до наносекунды, NaN/inf, точный Δt,
выбор более короткой допустимой пары с большим числом точек, отсутствие
результата и отсечение ТОП-10. Для каждого варианта набор строк повторно
сверяется с настоящим `prepare_compressor_plots`.

Синтетический benchmark с непустым ТОП-10, шагом 30 минут и 17 ячейками ВНА:

| Строк | Время, с | Лучший график, точек |
|---:|---:|---:|
| 500 | 0,340 | 168 |
| 1500 | 0,834 | 648 |
| 5000 | 2,775 | 2418 |

В сезонном контрольном наборе без подходящих пар 12000 строк заняли
19,618 с. Это измерения одного окружения, не гарантия времени на любых
данных. Конкретные новые книги пользователь проверит следующим этапом.

## Снимок и экспорт

Переключатели доступны в таблицах и графиках, метод 1 остаётся начальным.
Метод 2 рассчитывается лениво из снимка. Выбор пар хранится раздельно
для методов и периодов. Возврат к рассчитанному методу не запускает поиск.
Повторные входы/расчёт сбрасывают результаты. Просроченные задания
проверяются по снимку и идентификатору задания, не меняют новый результат
и не снимают признак занятости другого задания.

`CalculationSnapshot.with_compressor_algorithm` заменяет только таблицы
ТОП-10, параметры графиков компрессора и `period.vna_top1` в Word-контексте.
Границы, исходные данные, поправки, общие регрессии деградации ГТУ, РХ и
экономика сохраняются. Проверены переключения туда/обратно, независимость
выборов, ошибки и занятость, пустые результаты без fallback, Excel с
обратным чтением настоящих рядов диаграмм и совпадение условий Word.

## Интерфейс

Основные списки ТЭЦ/ГТУ/листа и списка пар используют тот же компонент,
что сопоставление каналов. Графитовое меню имеет скругление 13 px, заголовок,
галочку выбранной строки, отдельную подсветку наведения/клавиатуры,
прокрутку и ограничение границами экрана. Галочка не входит в текст значения.
Проверены настоящий ввод мышью, End/Enter/Escape, синхронизация с backend,
блокировка во время экспорта и все прежние сценарии маппинга единиц.

Шрифт HTML — Segoe UI Variable / Segoe UI / system-ui. Нативные окна
получили общую графитовую тему и Segoe UI 14 px; содержимое полного журнала
сохраняет моноширинный шрифт для чтения числовых записей. Выбор пары
и состояния элементов используют графитовые цвета. При высоте окна
до 690 px заголовки/отступы/малый журнал компактнее.

Графики ТОП-10 центрированы отдельной белой карточкой, высота начального
изображения до 360 px; есть − / «Вписать» / +. Масштаб хранится отдельно
для метода, периода и пары. Список периодов прокручивается вертикально.
Проверены реальные размеры DOM и снимки при 900×600, 1200×800, 1600×1000;
горизонтального выхода страницы за экран нет, меню остаются в границах.
`tests/qa_vna_algorithms_ui.py`, `qa_top10_preview_ui.py` и
`qa_mapping_controls_ui.py` прошли; ошибок JavaScript нет.
