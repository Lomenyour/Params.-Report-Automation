# Основная книга: параметры и расчётные зависимости

Реализовано по согласованию 03.11.2026. Это текущий сценарий Rotor Test;
исторические ограничения «только СызТЭЦ» относятся к прежней реализации.

## Пользовательский сценарий

1. Выбрать основную книгу, ТЭЦ и ГТУ. Измерения читаются только с первого
   листа «Данные».
2. Открыть «Колонки основной книги». Перед первым запуском для выбранного
   файла это окно предлагается обязательно. «Поправки ГТ» открывает ту же
   проверку с формулами и коэффициентами текущей книги.
3. Проверить для каждой колонки параметр, единицы, тип «Измеренный» или
   «Расчётный», выбранный вариант формулы. Вспомогательные колонки сохраняются
   и могут участвовать в зависимостях без назначения аналитического параметра.
   Если единиц в заголовке нет, предложенная единица отмечена как требующая
   проверки. Неоднозначные/дублирующиеся назначения требуют уточнения.
4. Подтвердить книгу. Только после этого записывается пользовательский JSON.
   Отмена не меняет справочник. Профиль относится к ТЭЦ/ГТУ; при перестановке
   уникальные заголовки позволяют восстановить назначения. История сохраняется.
5. В готовом режиме анализируются сохранённые производные значения. Паспорт
   передаёт объёмное Qнр в расчёт КПД ГТУ, но чужой профиль поправок не запускается.
6. В режиме импорта сначала подтверждается книга, затем обычный маппинг
   датчиков выбранного листа. В списке назначения доступны измеренные параметры
   и явно оставленные измеренными вспомогательные колонки. Дата и наработка
   определяются маппингом, а не фиксированными A/B.
7. Получасовые строки объединяются по датам, совпавшие измерения заменяются.
   Производные значения пересчитываются для новых/изменённых дат. Зависимые
   соседние средние также обновляются; готовая история вне области влияния
   сохраняется. Исходная книга не перезаписывается.
8. После аналитики Excel и Word формируются только соответствующими кнопками.

## Формулы и поправки

`scr/workbook_formulas.py` разбирает ограниченный набор Excel-выражений в дерево
операций. Python eval/exec, VBA, XLL и внешние книги не выполняются. Арифметика,
сравнения, IF/IFERROR, SUM/AVERAGE, AND/OR, MIN/MAX, ABS/SQRT/POWER,
ROUND/EXP/LN/LOG10 и вызовы CoolProp поддерживаются явно. Общие формулы
Excel раскрываются, относительные ссылки учитываются, циклы отклоняются.

Набор поправок Nприв берётся из фактических ссылок в формуле книги: пять
поправок не дополняются коэффициентами из восьмичленной схемы другой ГТУ.
Коэффициенты по ссылкам читаются из текущей книги, включая «Своя поправка»;
старые численные значения JSON-профиля СызТЭЦ не подставляются.

При разных выражениях в одном столбце окно показывает варианты и их частоту.
Большинство служит предложением, выбор подтверждает пользователь. Для
Ижевской пользователь подтвердил квадратичную температурную зависимость из
«Своя поправка»; первая строка с другим выражением не является эталоном.
Создание дополнительной поправки внутри приложения остаётся будущей задачей.

При импорте паспорт газа задаёт C/H, массовое/объёмное Qнр и плотность в
сопоставленных узлах. Для распознанного выражения нормального объёмного
расхода вида `(… × 3600) / числовая_плотность` знаменатель заменяется
построчной плотностью паспорта. В окне есть пояснение этой подстановки;
при отсутствии паспорта сохраняется исходное выражение книги.

IFERROR использует именно запасное значение исходного выражения и учитывается
в диагностике. Пустые показания датчиков не заменяются нулями в арифметике.
SUM/AVERAGE игнорируют пустые исходные ссылки; ошибки производных зависимостей
не превращаются в здоровые нули. Ошибки функций/нет коэффициента/цикл
останавливают неподдерживаемый пересчёт, а не запускают формулы другой станции.
Нефизичные термодинамические точки дают отсутствующий результат с диагностикой.

Формулы старых потерь и зависимые от них вспомогательные колонки исключаются.
Перерасход и недовыработка остаются за `economics.py`. Периоды, регрессии,
фильтры, наработка и тарифная методика этой доработкой не менялись.
В обоих режимах эти результаты записываются в лист «Данные», включая
станционный заголовок «Перерасход газа». Явно сопоставленное абсолютное
входное давление не переопределяется прежней эвристикой по отношению к Pатм.

## Сохранение и будущая БД

`%LOCALAPPDATA%/GTU_Report/workbook_mapping_profiles.json` содержит подтверждённые
назначения, единицы, выбор выражений, подписи структуры и историю по ТЭЦ/ГТУ.
Сырые данные и значения коэффициентов туда не записываются. Изменение формул
показывается при проверке; изменение файла сбрасывает подтверждение.

Снимок расчёта содержит реально использованное дерево выражений и коэффициенты.
Экспорт добавляет скрытый лист «Профиль расчёта». JSON разбивается на части,
чтобы не превысить предел 32767 символов ячейки Excel. Экспортированную книгу
можно использовать для нового импорта без первоначальных листов коэффициентов
и без локального справочника. При выборе другой ТЭЦ/ГТУ такой профиль отклоняется.

Аналитика получает общий DataFrame с именами физических параметров. Исполнитель
формул работает с переданными узлами и массивами, без фиксированных колонок
СызТЭЦ. Для будущей БД потребуется адаптер чтения измерений, соответствий и
коэффициентов; переписывать аналитику ВНА/РХ/экономики для этого не требуется.

## Границы поддержки

- Значения готовой книги читаются Calamine из поддерживаемых Excel-форматов.
- Извлечение формул реализовано для `.xlsx/.xlsm/.xltx/.xltm`. Для пересчёта
  новых строк из `.xls/.xlsb` нужно сначала сохранить основную книгу в `.xlsx`.
  Это явно сообщается; готовые значения сами по себе не являются формулами.
- Требуются все обязательные аналитические параметры, включая КПД компрессора.
  Отсутствующий столбец не подменяется другим показателем по сходству названия.
- Именованные диапазоны, произвольные функции, межкнижные ссылки, рекуррентные
  вычисления по собственным предыдущим значениям пока не поддерживаются.
- Пропуски/ошибки единиц/смысла датчиков требуют проверки; успешное выполнение
  дерева не доказывает достоверность измерений. Масштабы автоматически не угадываются.
