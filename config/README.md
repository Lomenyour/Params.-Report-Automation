# Справочники станций

`stations.json` — настройки приложения, не измерения датчиков. Файл содержит
связанные таблицы с устойчивыми ключами, рассчитанные на последующий перенос в БД:

| Таблица | Ключ / связь | Содержание |
| --- | --- | --- |
| `stations` | `id` | Название ТЭЦ и варианты её имени в названии файла. |
| `companies` | `id` | Генерирующие компании. |
| `turbines` | `station_id`, `number` | Обозначение ГТУ, полная модель, подключённая методика. |
| `tariffs` | `station_id → stations.id` | Газ, ЭЭ и себестоимость ЭЭ; один набор на ТЭЦ. |
| `sensor_parameters` | `id` | Смысл параметра и колонка принятой структуры листа «Данные». |
| `sensor_channels` | `station_id`, `unit_number`, `parameter_id` | Полный код датчика и коэффициент перевода единиц для конкретной ГТ. |
| `duplicate_channels` | `station_id`, `source_code` | Известные производные колонки, которые можно пропустить только после проверки совпадения значений. |

Каталог от 29.10.2026: 9 компаний, 33 объекта, 57 ГТУ из предоставленной
таблицы «ТЭЦ ГТ». Объединённые ячейки прочитаны по границам объединений,
каждая запись имеет ключ станции и строковый номер ГТУ. `11Б` и `11В` различны.
Проверенная методика `syz_tec_v1`, тарифы и каналы пока только для СызТЭЦ:
`id = syz_tec`, ГТУ-10 и ГТУ-11. Остальные объекты — справочник оборудования;
до подключения своей методики расчёт блокируется с объяснением. Отсутствующие
тарифы представлены отсутствием записи, в UI — пустыми полями.
Тарифы подтверждены пользователем 26.10.2026: газ — 7,773 руб/нм³,
электроэнергия — 2253,66 руб/МВт·ч, себестоимость — 1200 руб/МВт·ч.
В JSON используется точка, в интерфейсе можно вводить точку или запятую.
Ручная правка тарифа в окне действует на текущий расчёт и не переписывает справочник.

При добавлении ТЭЦ нужны её запись, набор тарифов и собственные коды каналов
со ссылками на параметры. Чужие коды не наследуются автоматически.
Колонки назначения пока соответствуют принятой структуре расчётной книги;
произвольная перестановка колонок книг не поддерживается этим справочником.

Названия моделей: `6FA → PG6111FA` по подтверждению пользователя;
`АЕ 64.3A → AE64.3A`, `LM 6000 PD → LM6000PD`. Исходные варианты сохранены
в `model_aliases`. Для ТЭЦ-26/ГТУ-1 задано `GT-26B` по уточнению пользователя.
Неизвестные модификации моделей не дополняются. Обозначения подтверждены
[GE для PG6111FA](https://www.ge.com/news/press-releases/first-uprated-ge-frame-6fa-gas-turbines-increase-performance-german-cogeneration-1),
[Ansaldo для AE64.3A](https://www.ansaldoenergia.com/fileadmin/Brochure/AnsaldoEnergia-GasTurbine-AE64.3A-20220930.pdf)
и [техническим документом GE для LM6000PD](https://www.ge.com/content/dam/gepower-pgdp/global/en_US/documents/technical/ger/ger-3695e-ge-aero-gas-turbine-design-op-features.pdf).

Модель — реквизит отчёта, она не подменяет профиль индивидуальной турбины.
Существующие ключи `syz_tec|10` и `syz_tec|11` сохранены, миграция пользовательских
паспортов и коэффициентов не нужна. Ручная ГТУ передаётся во все этапы явно.

`scr/station_profiles.py` предоставляет контракт `StationRepository` и
файловую реализацию `JsonStationRepository`. GUI и импорт обращаются к
контракту; реализацию чтения можно заменить БД, сохранив эти методы.
Распознавание выполняется по имени файла, неоднозначное или неизвестное
название требует ручного выбора. Ручной выбор имеет приоритет при импорте.

В исходниках используется `config/stations.json`. Тестовая сборка содержит
встроенную копию и копию рядом с EXE: `config/stations.json` рядом с EXE
имеет приоритет. После редактирования справочника приложение нужно перезапустить.
`build_gui.ps1` обновляет обе копии из проекта.

Сохранённые пользователем соответствия каналов лежат отдельно, в
`%LOCALAPPDATA%/GTU_Report/sensor_mappings.json`, с ключами ТЭЦ, номера ГТ
и набора заголовков. Прежние соответствия СызТЭЦ читаются при подтверждённом
совпадении имени станции; после сохранения используется новый ключ.

Получасовая дискретность, правила совмещения дат и расчётная методика
остаются прежними. Поддержка другой дискретности и самостоятельный пересчёт
всех производных колонок записаны в план `DATA_FLOW.md`.

Паспорт газа хранится отдельно:
`%LOCALAPPDATA%/GTU_Report/gas_passports.json`, ключ `station_id|unit`.
Станционные тарифы и назначения датчиков от его редактирования не меняются.
Реальные паспорта не включаются в Git. Порядок выбора, единицы и перенос
поправок в новую книгу описаны в разделе 16 `DATA_FLOW.md`.

Именованные коэффициенты (29.10.2026): отдельный пользовательский файл
`%LOCALAPPDATA%/GTU_Report/correction_profiles.json`, ключ `station_id|unit`.
Метод `syz_tec_v1` содержит 63 поля; формы и подсказки определяет
`scr/correction_profiles.py`. Их математические значения не входят в
`stations.json`, EXE или Git. Приоритет: JSON → именованный профиль в Excel.
Инструкция — `CORRECTION_PROFILES.md`, реализация — раздел 17 `DATA_FLOW.md`.
